# SINAMICS G120 family drives (PROFINET)

Applies to G120 with PN control units (CU240E-2 PN, CU250S-2 PN …) and G120C PN.

## TIA configuration
- Add the drive from the hardware catalogue (Startdrive) or its GSDML. The telegram in the HW config must match
  `p0922` on the drive.
- After choosing or changing a telegram, compile and read the **HW ID / system constant** from the PLC's system
  constants tab. Its name depends on the device name and telegram.
- A drive factory reset clears the PROFINET device name and IP. Re-assign them before testing comms.
- PROFIsafe telegrams (e.g. 30 for STO) need an F-CPU. On a standard CPU, safe stop stays hard-wired.

## PLC interface

### Standard telegram 1: speed control
- Siemens **SinaSpeed** (LSinaSpeed library), e.g. as a multi-instance in the project's drive FB.
  `HWIDSTW` = `HWIDZSW` = telegram HW ID; `RefSpeed` = drive `p2000`; `AckError` = fault reset; `PermitRun`
  = run permissive (e.g. not E-stop).
- Speed words are scaled 16384 = `p2000` and clamp at 32767, i.e. **200 % of `p2000`**.
- Telegram 1 has no current, torque or fault number.

### SIEMENS telegram 352 (PZD-6/6): speed plus current, torque and diagnostics
- Send: `STW1, NSOLL_A`, 4 × unused. Receive: `ZSW1, NIST_A_GLATT, IAIST_GLATT (r68), MIST_GLATT (r80),
  WARN_CODE (r2132), FAULT_CODE (r2131)`.
- SinaSpeed doesn't support 352. Read and write the 6 words consistently with `DPRD_DAT` / `DPWR_DAT` on the telegram HW ID:
  - `STW1 = 16#047E` (no OFF2/OFF3, enable operation, ramp enabled, setpoint enabled, control by PLC)
  - bit 0 = ON command (AND NOT `ZSW1.6`, switching on inhibited)
  - bit 7 = fault-acknowledge pulse
  - speed = word × `p2000` / 16384
  - current = word × `p2002` / 16384
  - torque = word × `p2003` / 16384
- One FB can support both telegrams with a `Tel352` input that selects the direct path or SinaSpeed. Drives on telegram 1
  are then unaffected.

## Gotchas
- **Max speed:** raising `p1082` alone doesn't get past 2 × `p2000`. Raise `p2000`, SinaSpeed `RefSpeed` and any PLC
  speed clamp together.
- **Ramps are referenced to `p1082`.** Raising it steepens the ramp (A07409, V/f Imax). Scale `p1120/p1121`,
  save with `p0971`, and check the active data set actually holds the new values.
- **Motor data must match the motor's actual connection.** For dual-voltage motors, check how it's wired against
  `p0304/p0305`. Wrong data gives wrong flux, which shows as speed short under load, slow acceleration, motor ID fault F07990, and a wrong
  `p0640` current limit.
- Output voltage (`r25`) vs DC link (`r70`) shows where field weakening starts. Check it before running above base frequency.
- After quick commissioning the motor ID is armed (A07991); the next ON command runs it.
- F08526 = no cyclic connection (PLC stopped, wrong telegram or device name).
- Drawings and BOMs can name the wrong control/power unit. Trust the drive's uploaded parameters.
- Startdrive has no parameter-value import. Hand over an ordered entry sheet (step, parameter, value, reason).
- **Call order:** a reset bit cleared by a block that runs before the drive block never reaches the drive. Use a
  per-drive reset bit or a latched copy.

## Per-project checklist
- [ ] Telegram in HW config = `p0922`; HW ID constant noted
- [ ] `RefSpeed` = `p2000`; for telegram 352 also `RefCurrent` = `p2002` and `RefTorque` = `p2003`
- [ ] Motor data checked against the nameplate *and* the actual connection
- [ ] `p1082`, ramps and the PLC speed clamp agree; data set saved
- [ ] Fault-reset source and its call order checked; drive faults mapped to alarms
- [ ] Parameter backup (upload + CSV export) archived after commissioning
